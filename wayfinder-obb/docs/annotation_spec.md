# 標註規範

## 原則

**每條斑馬線漆線一個旋轉框。** 不要用一個大框涵蓋整組斑馬線。

多條漆線互為冗餘觀測。部分遮擋或磨損時，仍可由其餘漆線融合出穿越軸，並以彼此的角度一致性互相檢查。單一大框只有一個角度估計，無從檢查。

---

## 旋轉框定義

| 項目 | 規範 |
|---|---|
| 格式 | Ultralytics OBB：每行 `cls x1 y1 x2 y2 x3 y3 x4 y4`，四個角點依順時針或逆時針排列，座標以影像寬高正規化到 0–1 |
| 角度 | 由四個角點決定，不另存角度欄位；Ultralytics 載入時轉為 `xywhr`（中心、寬高、旋轉角） |
| 長邊方向 | 沿漆線長軸 |
| 邊界 | 貼齊可見漆線邊緣，不含陰影與反光暈開 |
| 類別 | `0 zebra_stripe`（單一類別） |

---

## 收錄與排除

**要標：**
- 完整可見的漆線
- 部分遮擋，但仍能推定兩端邊界的漆線
- 磨損但輪廓仍可辨識的漆線

**不標：**
- 被遮擋到無法推定邊界
- 畫面邊緣被裁切過半
- 非斑馬線的白色標線：停止線、車道線、導引線。這類是主要混淆來源
- 兩條漆線之間的深色柏油縫隙（自動標註最常見的錯誤，見下方）

### 自動標註的檢查

本專案有部分影像以 SAM3 分割後轉成旋轉框。自動標註最常見的錯誤，是把兩條白紋之間的深色柏油縫隙當成一條漆線。
這類框內比兩側暗、亮度對比為負，可用簡單的內容檢查（框內與框外兩側的平均亮度差）擋掉。本專案以此剔除約 13.8% 的自動標註框。
錯框對訓練的傷害大於少一個框，篩選寧可保守。

## 號誌

| 項目 | 規範 |
|---|---|
| 格式 | Ultralytics detect：每行 `cls cx cy w h`，正規化座標 |
| 框範圍 | 整個行人號誌燈箱，含倒數秒數面板 |
| 類別 | 依亮起的燈色：`0 Green_Light`、`1 Red_Light` |
| 不收錄 | 車輛號誌、箭頭燈；倒數秒數只框進燈箱，不另外標註數字 |
| 背景圖 | 保留一部分不含號誌的街景（本專案驗證集約 6%），用來壓低誤報 |

---

## 切分

**以來源照片為單位切，不要隨機切。**

同一張照片的增強副本、同一路口的連續影格高度相似，隨機切會讓訓練與測試出現幾乎相同的畫面，分數會變成在量記憶。
本專案的原始資料集曾因此出現 test 有 94.5% 的影像來源與訓練重疊。

| 做法 | 說明 |
|---|---|
| 分組 | 去掉檔名中的增強後綴（例如 `_aug_NNN`）與資料平台雜湊，同一來源照片歸為一組 |
| 分桶 | 依組別雜湊分成 train／val／test 80／10／10 |
| 再檢查 | 確認 test 每張影像的來源都不出現在 train 或 val；不符合的另行剔除，留下乾淨的測試集 |
| 更嚴格的做法 | 有拍攝地點資訊時，改以路口為單位切分，讓測試集的路口完全沒出現在訓練中 |
